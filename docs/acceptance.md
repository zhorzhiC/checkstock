# Приёмка CheckStock

## Автоматические сценарии

Запуск: `docker compose run --rm app python -m pytest -q`.

| Требование | Проверка |
|---|---|
| Начальные приходы, нулевые остатки, отсутствие дублей seed | `test_seed_and_repeat_seed` |
| Приход и идемпотентность создания | `test_receipt_is_auditable_and_idempotent` |
| Резерв, отмена, отправка, несовместимые переходы | `test_fbs_reserve_cancel_ship` |
| Раздельные отправка/приёмка перемещения | `test_transfer_dispatch_and_receive_once` |
| FBO остаётся на маркетплейсе после приёмки | `test_fbo_receipt_keeps_marketplace_stock` |
| Зарезервированное нельзя списать | `test_reserved_goods_cannot_be_spent` |
| Локальная нехватка при достаточном общем запасе | `test_shortage_selected_ff_and_guided_replenishment` |
| Недостаточный общий запас / пустой выбранный ФФ | `test_empty_warehouse_and_insufficient_total` |
| Добавление, переименование, уникальность, архив | `test_warehouse_lifecycle_history_and_duplicate_names` |
| Удаление с остатком, запрет новых операций, вывоз | `test_archive_with_stock_allows_evacuation_not_new_work` |
| Архив с резервом / незавершённой приёмкой | `test_archive_allows_existing_fbs_completion`, `test_archive_allows_preexisting_incoming_transfer` |
| История названий | `test_renaming_preserves_document_names` |
| Нецелые/нулевые/отрицательные количества, чужие/несуществующие ID | `test_invalid_quantities_never_change_stock`, `test_invalid_identifiers_and_routes`, `test_store_isolation` |
| Гонки резервов и ключей | `test_concurrent_last_units_have_single_winner`, `test_concurrent_identical_key_creates_one_document` |
| Двойная приёмка / отправка против отмены | `test_concurrent_receive_is_applied_once`, `test_concurrent_ship_and_cancel_are_exclusive` |
| Прерывание после первой проводки откатывает всё | `test_unexpected_failure_rolls_back_all_postings` |
| Ограничения БД и неизменяемость журнала | `test_database_rejects_invalid_balance_and_journal_edits` |
| Сквозной баланс 9 + 3 + 4 = 16 | `test_complete_demo_scenario` |

Каждый HTTP-хелпер после запроса дополнительно сверяет позиции с проводками, количество принятых извне единиц с суммой по местам и резерв/транзит с документами. Проверка выполняется и после отказов.

## Ручная проверка интерфейса

- Главный экран: все три SKU, оба ФФ, включая нули; физический остаток, резерв и доступность читаются отдельно.
- Ошибка нехватки сохраняет форму и предлагает конкретное перемещение. До приёмки доступность получателя не увеличивается.
- Документ в работе содержит подходящее действие. Завершённое перемещение допускает безопасную проверку повтора.
- Архив с товаром остаётся в остатках; доступность к отправке не включает его. Вывоз и завершение начатых документов доступны.
- Поиск без совпадений показывает пустое состояние. Сброс фильтра возвращает строки.
- Escape закрывает диалог; Tab остаётся внутри открытого диалога; фокус и подписи элементов видны.
- При 1280 и 1440 px таблица и формы читаемы; при добавлении складов горизонтальная прокрутка находится внутри таблицы.
- При сетевой ошибке видны повтор загрузки или сообщение безопасного повтора команды.

## Проверка воспроизводимости

Из чистого клона поднять отдельный Compose-проект на свободном порту. Дождаться здоровых контейнеров, открыть экран, выполнить тесты. Перезапустить приложение и убедиться, что количество документов и история не изменились, seed не повторился. Сверить `/health` и `/api/v1/stock`.

Фактически выполненные проверки и ограничения последней сдачи фиксируются в `verification.md`.
